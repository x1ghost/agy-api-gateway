# Compatibility and operational boundaries

The public surface currently implements `POST /v1/messages`, `GET /v1/models`, health, and a bridge-specific cancellation endpoint. Token counting returns an explicit error on this transport. It is not a drop-in implementation of the entire Anthropic API.

Message requests must contain a recognized Claude Code or DeepSeek Harness identity in their system instructions, or use the DeepSeek Harness product User-Agent. Other or absent identities return HTTP 400 before forwarding. These identifiers are not client authentication: a caller can supply the same text or header, and a client update may change them.

Messages support text, streamed or buffered output, client-provided tool schemas, parallel tool calls and results, inline base64 PNG/JPEG/WebP, and adaptive thinking with private signature references. The server stores the provider's original signatures privately to restore tool and thinking history; edited or missing records fail instead of fabricating signatures. For Claude models, streamed thinking fragments are reassembled into their original signed block for replay; empty text-only fragments are omitted. One AGY ACP process hosts separate concurrent sessions for the selected account. The default concurrency limit is eight; `AGY_ACP_CONCURRENCY` can set it from 1 to 64, and excess requests wait. Sessions can use different models. After at least 32 sessions the process is retired when idle, without interrupting active sessions. Switching accounts also replaces the process. Model discovery and quota refresh may start separate short-lived CLI processes. Retries with the same idempotency key replay the recorded response; requests without a key receive independent scopes.

URL images, documents, assistant prefill, numeric thinking budgets, structured output, nonempty stop sequences and some tool options are rejected. Model and generation parameter semantics differ between providers. Limits, all tools, long outputs, arbitrary failures, and interoperability across every SDK version remain unverified. There is no guarantee of exactly-once client-side tool execution after a client crash.

System instructions are transformed: case-insensitive occurrences of `Claude` and `Anthropic` become `Antigravity`, except `CLAUDE.md` filenames. Recognizable client identity lines, including the standard DeepSeek Harness identity, become the AGY identity, and recognizable billing header lines are removed. Recognizable CC product availability, fast mode and model catalog bullets are removed. Recognizable DeepSeek Harness source and Web GUI guidance paragraphs are also removed. A known previously refused safety paragraph is replaced by the AGY native safety instruction by default. Set `AGY_CC_NATIVE_SECURITY_SWAP=0` to preserve that paragraph and retain the local refusal preflight. Tool descriptions replace standalone `Claude` and `Anthropic` with `Antigravity` while preserving path-like tokens; tool names and parameter schemas are unchanged. User messages and tool results are not filtered by this policy.

The proxy permits only a fixed set of CLI bootstrap destinations and the observed model route. Upstream protocol changes can break the gateway. It is deliberately fail-closed on non-429 upstream errors or ambiguous interrupted forwarding; an upstream 429 is returned to its caller without blocking later requests. Private state contains model responses and tool data; do not publish it.

Model discovery runs the signed-in official CLI's `agy models` with a five-minute in-memory cache; it does not make an inference request or verify quota. The list includes the original AGY IDs and `claude-agy/` aliases for IDs without Claude or Anthropic in their name, so Claude Code's discovery picker can display them. The gateway maps those aliases back to the original ID before routing. `created_at` is a required placeholder because the CLI does not report release dates. Enable Claude Code discovery with `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` and set `CLAUDE_CODE_GATEWAY_MODEL_DISCOVERY_TIMEOUT_MS=65000` for a cold CLI startup. When switching models, the gateway follows observed AGY behavior: it keeps visible messages and tool calls/results, while omitting the previous model’s thinking and signatures. Same-model continuation retains its original signatures.

For non-200 upstream responses, the gateway relays a bounded JSON error object and `Retry-After` when supplied. Non-JSON, compressed, or oversized/truncated error bodies may only yield the HTTP status. Error responses may be retained in the private response journal. The gateway sets `x-should-retry: false` and does not retry a refused request.

Generation diagnostics are written as one `agy_request` JSON line to standard error by default (systemd deployments can use `journalctl -u <service>`). They include request ID, model ID, upstream or gateway status, elapsed time, system-instruction SHA-256 and byte length, native-safety replacement count, message/tool counts, output settings, and reported token usage when available. They do not contain prompts, system text, tool data, response text, tokens or upstream error bodies. Hashes can correlate matching instructions and should still be treated as private metadata. Set `AGY_DIAGNOSTICS=0` to disable these lines.

For operator recovery from an understood non-429 upstream failure, stop the gateway, verify that no request is in flight and there are no control errors, and back up the private proxy state. The `acknowledgedStatusCount` field is the number of existing status entries reviewed; setting it to the current status count and clearing `refused` preserves the full counts and history. Do not acknowledge an unknown interruption; future non-429 errors still stop forwarding.
